# InvestRing 数据库设计文档

> 用途：定义 InvestRing 项目的数据库表结构、字段约束和计算逻辑。
> 核心内容：21张表（核心业务13张+日志系统7张+幂等性缓存1张）、净值计算公式、收益率计算、索引定义。
> 日志系统表定义来源：08-日志系统设计.md

---

## 1. 表结构定义

### 1.1 investor（投资人表）

```sql
CREATE TABLE investor (
    code VARCHAR(20) PRIMARY KEY,            -- 投资人编码
    name VARCHAR(50) NOT NULL,
    role VARCHAR(20) DEFAULT 'viewer',       -- admin/viewer
    phone VARCHAR(20),
    email VARCHAR(100),
    password_hash VARCHAR(255) NOT NULL,     -- bcrypt 哈希密码
    last_login_at TIMESTAMP,                 -- 最后登录时间
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**认证规则**：
- 所有用户（admin/viewer）必须设置密码
- 密码使用 bcrypt 哈希存储（cost factor: 10）
- 登录成功后更新 `last_login_at`

### 1.2 portfolio（投资组合表）

```sql
CREATE TABLE portfolio (
    code VARCHAR(20) PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    description TEXT,
    status VARCHAR(20) DEFAULT 'draft',     -- draft/active/closed
    started_at TIMESTAMP,                    -- 开始运行时间（首次申购确认时）
    closed_at TIMESTAMP,                     -- 关闭时间
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**状态定义**：

| status | 说明 | 触发条件 |
|--------|------|----------|
| draft | 草稿状态 | 组合创建时 |
| active | 运行中 | 首次申购确认后 |
| closed | 已关闭 | 执行关闭流程后 |

**生命周期字段**：
- `started_at`：首次申购确认时设置，标记组合正式运行时间
- `closed_at`：执行关闭流程时设置，标记组合关闭时间

**净值查询**：`SELECT unit_price, total_value, total_shares FROM portfolio_value_snapshot WHERE portfolio_code = ? ORDER BY snapshot_date DESC LIMIT 1;`

### 1.3 investor_holding（组合份额持有快照表）

```sql
CREATE TABLE investor_holding (
    id INTEGER PRIMARY KEY AUTO_INCREMENT,
    portfolio_code VARCHAR(20) NOT NULL,         -- 组合编码
    investor_code VARCHAR(20) NOT NULL,          -- 投资人编码
    shares DECIMAL(15,4) NOT NULL,               -- 持有份额
    frozen_shares DECIMAL(15,4) DEFAULT 0,       -- 冻结份额（赎回中）
    cost_per_share DECIMAL(10,4),                -- 成本价（加权平均）
    snapshot_date DATE NOT NULL,                 -- 快照日期
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (portfolio_code) REFERENCES portfolio(code),
    FOREIGN KEY (investor_code) REFERENCES investor(code),
    UNIQUE KEY (portfolio_code, investor_code, snapshot_date)
);
```

**查询当前份额**：`WHERE snapshot_date = (SELECT MAX(snapshot_date) FROM investor_holding WHERE portfolio_code = ? AND investor_code = ?)`

**冻结字段说明**：
- `frozen_shares`：如实记录快照生成时刻的冻结份额（当时 pending 状态的赎回总和）
- 快照每天晚上生成，此时可能存在 T+1/T+2 确认的 pending 交易
- 快照中 frozen 字段是历史记录，查询可用份额时仍需实时计算

**查询可用份额（实时计算）**：
```sql
-- 可用份额 = 快照份额 - pending赎回总和 - confirmed赎回（快照未生成）
SELECT 
    h.shares - COALESCE(
        (SELECT SUM(s.shares) 
         FROM subscription s 
         WHERE s.portfolio_code = h.portfolio_code 
           AND s.investor_code = h.investor_code 
           AND s.sub_type = 'redeem' 
           AND s.status = 'pending'),
        0
    ) - COALESCE(
        (SELECT SUM(s.shares) 
         FROM subscription s 
         WHERE s.portfolio_code = h.portfolio_code 
           AND s.investor_code = h.investor_code 
           AND s.sub_type = 'redeem' 
           AND s.status = 'confirmed'
           AND s.confirm_date > h.snapshot_date),
        0
    ) AS available_shares
FROM investor_holding h
WHERE h.portfolio_code = ? 
  AND h.investor_code = ?
  AND h.snapshot_date = (
    SELECT MAX(snapshot_date) 
    FROM investor_holding 
    WHERE portfolio_code = ? AND investor_code = ?
  );
```

**注**：查询可用份额必须实时计算，原因：
1. 快照生成后可能发生新的 pending 交易
2. 快照生成后可能有交易被取消
3. 已确认的交易快照可能还未生成

**查询历史份额**：按日期范围查询

**成本价计算**：首次 = 组合净值，后续 = `(old×cost + new×price) / (old + new)`

**业务逻辑**：
- 快照每天汇总生成一次（非每次交易后立即生成）
- 生成前提：净值和分红事件更新完成 + 当天应确认的交易都已处理完
- 快照表只增不改，保留完整历史
- **快照只记录有份额的状态**，不用于"占位"或"标记关系"
- **特殊情况**：移除投资人时创建 shares=0 的特殊快照，标记投资人已退出

### 1.5 product（产品信息表）

```sql
CREATE TABLE product (
    code VARCHAR(10) NOT NULL,
    market VARCHAR(20),                          -- CN_EXCHANGE/CN_OTC/HK_MUTUAL/NULL（可NULL，现金类产品无市场）
    name VARCHAR(100) NOT NULL,
    product_type VARCHAR(20) NOT NULL,             -- ETF/OEF/LOF/CASH
    asset_class_code VARCHAR(30),
    confirm_days INTEGER,                       -- 确认天数：场内0/场外1/QDII 2（自动计算）
    is_qdii BOOLEAN DEFAULT FALSE,
    data_source VARCHAR(20) DEFAULT 'tushare',
    fallback_source VARCHAR(20),
    data_source_status VARCHAR(20) DEFAULT 'pending',  -- pending/success/failed
    last_sync_at TIMESTAMP,
    sync_error TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (code, market),
    FOREIGN KEY (asset_class_code) REFERENCES asset_classification(code)
);
```

**产品类型**：

| 类型 | 说明 | 数据来源 |
|------|------|----------|
| ETF | 场内交易基金 | 收盘价（CN_EXCHANGE） |
| OEF | 开放式基金 | 净值（CN_OTC） |
| LOF | 上市开放式基金 | 场内收盘价/场外净值（按market区分） |
| CASH | 现金类资产（含货币基金） | 无 |

**确认天数自动计算规则**：

| 条件 | confirm_days | 说明 |
|------|-------------|------|
| market = CN_EXCHANGE | 0 | 场内交易，当天确认 |
| market = CN_OTC 且 is_qdii = FALSE | 1 | 场外基金，T+1确认 |
| market = CN_OTC 且 is_qdii = TRUE | 2 | QDII基金，T+2确认 |

**LOF基金交易方式说明**：

LOF（上市开放式基金）有两种交易方式，需根据实际操作选择对应的记录：

| 交易方式 | 使用记录 | confirm_days | 说明 |
|----------|----------|--------------|------|
| 场内买卖 | market=CN_EXCHANGE | 0 | 像股票一样在交易所买卖，T日买入T+1可卖 |
| 场内申赎 | market=CN_OTC | 1 | 通过交易所通道申购/赎回，走场外流程，T+1确认 |

**注意**：用户通过券商APP操作LOF时，需明确是"买卖"还是"申赎"，系统根据操作类型选择对应的记录进行交易确认。

**市场-数据源映射**：

| 市场 | 数据源 | 接口 | 字段 |
|------|--------|------|------|
| CN_EXCHANGE | tushare | fund_daily | unit_price（收盘价） |
| CN_OTC | tushare | fund_nav | unit_price（净值） |
| HK_MUTUAL | akshare | 基金接口 | unit_price（净值） |
| NULL | - | - | 无 |

**LOF拆分方案**：同一LOF产品拆分为两条记录：
- `code=161725, market=CN_EXCHANGE` → 场内，用fund_daily
- `code=161725, market=CN_OTC` → 场外，用fund_nav

### 1.7 portfolio_position（持仓快照表）

```sql
CREATE TABLE portfolio_position (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    portfolio_code VARCHAR(20) NOT NULL,
    platform_code VARCHAR(20),
    product_code VARCHAR(10) NOT NULL,          -- 基金代码或 CASH
    market VARCHAR(20) NOT NULL,               -- CN_EXCHANGE/CN_OTC/HK_MUTUAL/NULL
    shares DECIMAL(15,4),                       -- 份额（基金持仓）
    frozen_shares DECIMAL(15,4) DEFAULT 0,      -- 冻结份额（快照时刻pending卖出总和）
    cost_price DECIMAL(10,4),                   -- 成本价（加权平均）
    unit_price DECIMAL(10,4),                   -- 单位价格（场内=收盘价，场外=单位净值）
    market_value DECIMAL(15,4) DEFAULT 0,
    amount DECIMAL(15,4),                       -- 金额（现金持仓）
    frozen_amount DECIMAL(15,4) DEFAULT 0,      -- 冻结金额（快照时刻pending买入总和）
    snapshot_date DATE NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (portfolio_code) REFERENCES portfolio(code),
    FOREIGN KEY (platform_code) REFERENCES platform(code),
    FOREIGN KEY (product_code, market) REFERENCES product(code, market),
    UNIQUE(portfolio_code, product_code, market, platform_code, snapshot_date),
    CHECK (
        -- 净值型资产：有份额，无金额
        (shares IS NOT NULL AND amount IS NULL) OR
        -- 非净值型资产：无份额，有金额（现金类 product_code = CASH）
        (shares IS NULL AND amount IS NOT NULL)
    )
);
```

**查询当前持仓**：`WHERE snapshot_date = (SELECT MAX(snapshot_date) FROM portfolio_position WHERE portfolio_code = ?)`

**冻结字段说明**：
- `frozen_shares`：如实记录快照生成时刻的冻结份额（当时 pending 状态的卖出总和）
- `frozen_amount`：如实记录快照生成时刻的冻结金额（当时 pending 状态的买入总和）
- 快照每天晚上生成，此时可能存在 T+1/T+2 确认的 pending 交易
- 快照中 frozen 字段是历史记录，查询可用份额时仍需实时计算

**查询可用份额（实时计算）**：
```sql
-- 基金可用份额 = 快照份额 - pending卖出总和 - confirmed卖出总和（快照未生成）
SELECT 
    p.shares - COALESCE(
        (SELECT SUM(t.shares) 
         FROM trade t 
         WHERE t.portfolio_code = p.portfolio_code 
           AND t.product_code = p.product_code 
           AND t.market = p.market
           AND t.trade_type = 'sell' 
           AND t.status = 'pending'),
        0
    ) - COALESCE(
        (SELECT SUM(t.shares) 
         FROM trade t 
         WHERE t.portfolio_code = p.portfolio_code 
           AND t.product_code = p.product_code 
           AND t.market = p.market
           AND t.trade_type = 'sell' 
           AND t.status = 'confirmed'
           AND t.trade_date > p.snapshot_date),
        0
    ) AS available_shares
FROM portfolio_position p
WHERE p.portfolio_code = ? 
  AND p.product_code = ?
  AND p.market = ?
  AND p.snapshot_date = (
    SELECT MAX(snapshot_date) 
    FROM portfolio_position 
    WHERE portfolio_code = ? AND product_code = ? AND market = ?
  );
```

**成本价计算**：首次买入 = 买入价；后续买入 = `(old×cost + new×price) / (old + new)`；卖出不变

### 1.8 subscription（申购赎回记录表）

```sql
CREATE TABLE subscription (
```

**状态流转**：`pending → confirmed` 或 `pending → cancelled`

### 1.9 trade（组合调仓记录表）

```sql
CREATE TABLE trade (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    portfolio_code VARCHAR(20) NOT NULL,
    platform_code VARCHAR(20),
    product_code VARCHAR(10) NOT NULL,
    market VARCHAR(20),                       -- CN_EXCHANGE/CN_OTC/HK_MUTUAL/NULL
    trade_type VARCHAR(10) NOT NULL,          -- 'buy'/'sell'
    transfer_group VARCHAR(36),                -- 平台间现金转移配对标识
    shares DECIMAL(15,4),                       -- 卖出份额
    amount DECIMAL(15,4) NOT NULL,              -- 买入金额
    price DECIMAL(10,4),                         -- 成交价
    fee DECIMAL(15,4) DEFAULT 0,
    actual_amount DECIMAL(15,4),               -- 实际金额（含手续费）
    trade_date DATE NOT NULL,
    confirm_date DATE,
    status VARCHAR(20) DEFAULT 'pending',      -- pending/confirmed/cancelled
    notes TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (portfolio_code) REFERENCES portfolio(code),
    FOREIGN KEY (platform_code) REFERENCES platform(code),
    FOREIGN KEY (product_code, market) REFERENCES product(code, market)
);
```

**transfer_group 说明**：
- 用于平台间现金转移，同一次转移的两条 Trade 记录（卖出 + 买入）共享同一个 `transfer_group` 值
- 普通调仓交易此字段为 NULL

**金额计算**：
- 买入：`amount = actual_amount - fee`，`shares = amount / price`
- 卖出：`amount = actual_amount + fee`，`shares = amount / price`

**现金中转约束**：
- 调仓必须通过现金中转，不能直接基金对基金转换
- 卖出基金：所得资金进入组合现金池（需等待确认）
- 买入基金：从组合现金池支出（只能使用已有可用现金）
- 卖出pending不自动增加可用现金

**状态流转**：
- 场内：`pending → confirmed`（当天确认，使用收盘价）
- 场外：`pending → confirmed/cancelled`（T+1确认，使用T日净值）
- QDII：`pending → confirmed/cancelled`（T+2确认）

### 1.11 share_change_event（份额变动事件表）

```sql
CREATE TABLE share_change_event (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    -- 持仓定位
    portfolio_code VARCHAR(20) NOT NULL,
    product_code VARCHAR(10) NOT NULL,
    market VARCHAR(20) NOT NULL,
    -- 事件类型与日期
    event_type VARCHAR(30) NOT NULL,         -- cash_dividend/reinvest_dividend/share_split/share_merge/bonus_share/forced_adjustment
    ex_date DATE NOT NULL,                   -- 除息/除权日（应用日）
    entitlement_date DATE NOT NULL,           -- 权益登记日
    platform_code VARCHAR(20),                 -- 现金归属平台（平台级事件必填，基金级事件为空）
    parent_event_id INTEGER,                    -- 父事件ID（基金级事件拆分后的子记录指向父记录）
    event_source VARCHAR(20) NOT NULL,        -- tushare/manual
    -- 权益份额
    entitlement_shares DECIMAL(15,4),         -- 权益登记日持有份额
    -- 份额变化
    shares_before DECIMAL(15,4),
    shares_change DECIMAL(15,4),
    shares_after DECIMAL(15,4),
    -- 事件参数
    ratio DECIMAL(10,4),                     -- 拆分/合并/送股比例
    div_cash DECIMAL(10,4),                  -- 每份分红金额
    reinvest_nav DECIMAL(10,4),             -- 再投资净值
    -- 现金影响
    cash_change DECIMAL(15,4),               -- 现金变化金额
    cash_product_code VARCHAR(10),          -- 现金分红落入账户
    -- 状态
    status VARCHAR(20) DEFAULT 'pending',   -- pending/confirmed/cancelled
    tushare_event_id VARCHAR(50),
    notes TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    confirmed_at TIMESTAMP,
    FOREIGN KEY (portfolio_code) REFERENCES portfolio(code),
    FOREIGN KEY (platform_code) REFERENCES platform(code),
    FOREIGN KEY (parent_event_id) REFERENCES share_change_event(id),
    FOREIGN KEY (product_code, market) REFERENCES product(code, market)
);
```

**事件类型与计算逻辑**：

| event_type | 份额变化 | 现金变化 | 计算公式 |
|------------|---------|---------|---------|
| cash_dividend | 不变 | 增加 | cash_change = entitlement_shares × div_cash |
| reinvest_dividend | 增加 | 不变 | shares_change = entitlement_shares × div_cash / reinvest_nav |
| share_split | 增加 | 不变 | shares_after = entitlement_shares × ratio |
| share_merge | 减少 | 不变 | shares_after = entitlement_shares / ratio |
| bonus_share | 增加 | 不变 | shares_change = entitlement_shares × ratio |
| forced_adjustment | 指定 | 指定 | 直接填写 shares_change / cash_change |

**权益登记日校验规则**：
- 权益登记日必须是交易日（创建事件时校验）
- 查询 `trading_calendar` 表确认 `is_open = true`
- 若非交易日，返回错误：`{ error: "INVALID_ENTITLEMENT_DATE", message: "权益登记日必须是交易日" }`

**事件状态与持仓快照校验**：
- **创建事件时**：status = 'pending'，不校验持仓快照是否存在
- **确认事件时**：必须校验权益登记日对应的 `portfolio_position` 快照是否存在
- 若快照不存在，返回错误：`{ error: "MISSING_POSITION_SNAPSHOT", message: "权益登记日持仓快照不存在，请先生成快照" }`

### 1.12 portfolio_value_snapshot（组合市值快照表）

```sql
CREATE TABLE portfolio_value_snapshot (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    portfolio_code VARCHAR(20) NOT NULL,
    snapshot_date DATE NOT NULL,
    total_value DECIMAL(15,4) NOT NULL,
    total_shares DECIMAL(15,4) NOT NULL,
    unit_price DECIMAL(10,4) NOT NULL,
    unit_price_change_pct DECIMAL(8,4),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (portfolio_code) REFERENCES portfolio(code),
    UNIQUE(portfolio_code, snapshot_date)
```

## 2. 核心计算公式

### 2.1 市值计算

```
组合总市值 = Σ(场内份额 × 收盘价) + Σ(场外份额 × 净值) + Σ(非净值型资产金额)
组合净值 = 组合总市值 / 组合总份额

**可用现金（实时计算）**：
```
组合可用现金 = 最新快照现金
            + SUM(confirmed申购金额 WHERE 快照未生成)
            - SUM(confirmed赎回金额 WHERE 快照未生成)
            - SUM(pending买入金额)
            - SUM(confirmed买入金额 WHERE 快照未生成)
            + SUM(confirmed卖出金额 WHERE 快照未生成)
```

> ⚠️ **重要**：可用现金必须实时计算，不能仅读取快照。详见 03-业务流程设计.md "可用资金计算规则" 章节。
```

### 2.2 QDII净值获取

QDII基金净值T+2公布，需向前查找最多3个交易日：

```python
def get_nav(product_code, target_date):
    if not is_qdii(product_code):
        return query_price(product_code, target_date)
    for offset in range(4):
        date = prev_trading_day(target_date, offset)
        nav = query_price(product_code, date)
        if nav: return nav
    raise ValueError(f"无法获取QDII产品{product_code}的有效净值")
```

### 2.3 资金流计算

```
资金流入 = Σ(subscription.amount WHERE sub_type='subscribe' AND status='confirmed')
资金流出 = Σ(subscription.amount WHERE sub_type='redeem' AND status='confirmed')
净流入 = 资金流入 - 资金流出
```

### 2.4 收益率计算

**累计收益率**：
```
(当前净值 - 初始净值) / 初始净值 × 100%
```

**年化收益率**：
```
(当前净值 / 初始净值)^(365 / 持有天数) - 1
```

**时间加权收益率（TWR）**：
```
TWR = (1 + r₁) × (1 + r₂) × ... × (1 + rₙ) - 1
其中 rᵢ = (期末复权净值 - 期初复权净值) / 期初复权净值
复权净值使用 accumulated_nav 字段计算
```

## 5. SQLite 并发配置

SQLite 是文件数据库，默认情况下写操作会锁定整个数据库。为支持定时任务与手动操作的并发场景，需进行以下配置：

### WAL 模式

```python
# SQLAlchemy 连接配置
from sqlalchemy import event

@event.listens_for(engine, "connect")
def set_sqlite_pragma(dbapi_connection, connection_record):
    cursor = dbapi_connection.cursor()
    cursor.execute("PRAGMA journal_mode=WAL")      # 写前日志模式
    cursor.execute("PRAGMA busy_timeout=30000")    # 30秒锁等待超时
    cursor.execute("PRAGMA synchronous=NORMAL")    # 同步模式（性能优化）
    cursor.close()
```

**WAL 模式优势**：
- 读写可并发：读操作不阻塞写操作，写操作不阻塞读操作
- 性能提升：减少磁盘 I/O
- 适用场景：读多写少（本项目的典型场景）

### 并发注意事项

| 场景 | 处理方式 |
|------|----------|
| 定时任务执行净值同步 + admin 手动触发市值计算 | WAL 模式下可并发，但建议通过任务调度器串行化 |
| 多个组合同时计算净值 | 可并发读取，写入时自动排队 |
| 大量数据导入 | 建议暂停定时任务，导入完成后再启用 |

### 6.8 idempotency_cache（幂等性缓存表）

```sql
CREATE TABLE idempotency_cache (
    `key` VARCHAR(100) PRIMARY KEY,    -- Idempotency-Key（UUID）
    portfolio_code VARCHAR(20) NOT NULL, -- 组合编码
    request_hash VARCHAR(64) NOT NULL,  -- 请求体哈希（用于校验）
    response TEXT NOT NULL,            -- 响应结果（JSON）
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    expires_at TIMESTAMP NOT NULL      -- 过期时间（建议24小时）
);
```

**用途**：
- 用于批量调仓等非幂等接口的幂等性控制
- 防止网络重试导致的重复交易
- 客户端需在请求头中传递 `X-Idempotency-Key`

**使用场景**：
- `POST /api/portfolios/{portfolio_code}/trades/batch` - 批量调仓
- 其他需要幂等性保证的创建类接口

**清理机制**：
- 定时任务清理过期记录（`expires_at < CURRENT_TIMESTAMP`）
- 建议每天凌晨清理一次
