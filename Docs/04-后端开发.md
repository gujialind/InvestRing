# InvestRing 后端开发文档

> 用途：定义后端 API 接口规范。
> 核心内容：75个接口、14个模块，包含认证、投资人管理、组合管理、持仓管理、交易管理、数据同步、日志系统等。

---

## 1. 认证模块（2个接口）

### 登录
```
POST /api/auth/login
Body: { code: string, password: string }
Response: { 
  token: string,           // HMAC 签名 token，格式：{user_code}:{timestamp}:{signature}
  expires_at: timestamp,   // 过期时间（7天）
  user: { code, name, role }
}
规则：
- 验证用户编码和密码
- 密码错误返回 401
- 连续失败 5 次锁定账户 15 分钟
- 登录成功更新 last_login_at
说明：
- Token 有效期 7 天，期间无需重新登录
- 如需"登出"，清除浏览器中的 Token 即可
- Token 过期后需重新登录
```

### 修改密码
```
PUT /api/auth/password
Headers: Authorization: Bearer {token}
Body: { 
  target_code?: string,    // 目标用户编码（仅 admin 可指定）
  old_password?: string,   // 原密码（修改自己密码时必填）
  new_password: string     // 新密码
}
Response: { message: "密码修改成功" }
规则：
- admin 可修改任意用户密码，无需原密码
- viewer 只能修改自己密码，需验证原密码
- 新密码长度 6-32 位
- 修改密码后原 token 失效，需重新登录
安全建议：
- 如怀疑 Token 泄露，可通过修改密码强制所有 Token 失效
- 建议定期修改密码
```

### Token 认证机制

```
Token 格式：{user_code}:{timestamp}:{signature}
- user_code: 用户编码
- timestamp: 生成时间戳（秒）
- signature: HMAC-SHA256(user_code:timestamp, SECRET_KEY)

验证流程：
1. 解析 token 获取 user_code、timestamp、signature
2. 检查 token 是否在黑名单（已登出）
3. 检查 timestamp 是否过期（7天有效期）
4. 验证 signature 是否正确
5. 查询用户信息，附加到请求上下文

权限控制：
- 所有接口需要认证（除 /api/auth/login）
- admin 可访问所有接口
- viewer 只能访问查询类接口，调用管理接口返回 403
```

## 2. 投资人管理模块（5个接口）

### 创建投资人
```
POST /api/investors
Body: { name, role?: string, phone?: string, email?: string, password: string }
Response: { code, name, role, created_at }
规则：
- password 必填，使用 bcrypt 哈希存储
- 默认 role = 'viewer'
```

### 获取投资人列表
```
GET /api/investors
Query: role?: string
Response: [ { code, name, role, phone, email, created_at } ]
```

### 获取投资人详情
```
GET /api/investors/{code}
Response: { code, name, role, portfolios: [...], total_value }
```

### 更新投资人
```
PUT /api/investors/{code}
Body: { name?, role?, phone?, email?, password? }
Response: { code, name, role, updated_at }
规则：
- password 可选，如提供则更新密码哈希
```

### 移除投资人（从组合中移除）
```
DELETE /api/portfolios/{portfolio_code}/investors/{investor_code}
Response: { message: "移除成功" }
规则：
- 实时检验投资人可用份额 = 0（快照份额 - pending赎回 - confirmed赎回快照未生成）
- 若可用份额 > 0：拒绝，提示"投资人仍有份额，需先全部赎回"
- 创建移除快照（shares=0），标记投资人已退出组合
- 后续快照生成时跳过该投资人
- 投资人记录保留，仅退出该组合
```

> ⚠️ **说明**：
> - 投资人通过首次申购自动"加入组合"，无需单独添加
> - 移除投资人是业务操作，投资人记录永久保留（不支持物理删除）

```
GET /api/portfolios/{code}/returns
Query: start_date?, end_date?, return_type?: cumulative | annualized | twr
```

```
GET /api/portfolios/{code}/cash-flow

```

### 获取安全日期
```
GET /api/portfolios/{code}/safe-date
Response: { safe_date, pending_events: [...] }
规则：安全日期 = MIN(待确认事件日期) - 1，无待确认事件时为昨天
```

### 手动触发净值计算
```
POST /api/portfolios/{code}/calculate
Body: { date? }  // 默认计算到昨天

```

### 历史净值重算
```
POST /api/portfolios/{code}/recalculate
Body: { start_date, end_date }
Response: { status: "completed", snapshots_deleted: number, snapshots_created: number }
规则：删除指定日期范围内的快照，重新计算
用途：修正历史数据错误或补充缺失快照
```

### 关闭组合
```
POST /api/portfolios/{code}/close
Body: { reason? }
Response: { code, status: "closed", closed_at }
规则：
- 仅 admin 可执行
- 已关闭组合禁止申购/赎回/调仓
- 组合数据保留，可查询历史记录
```

### 重新激活组合
```
POST /api/portfolios/{code}/reactivate
Response: { code, status: "active", reactivated_at }
规则：
- 仅 admin 可执行
- 仅已关闭组合可激活
- 激活后可正常申购/赎回/调仓
```

### 删除组合
```
DELETE /api/portfolios/{code}
Response: { message: "删除成功" }
规则：
- 仅 admin 可执行
- 仅 draft 状态组合可删除（active/closed 状态禁止删除）
- 删除时同步清理关联的 pending 申购记录（如有）
- 组合删除后不可恢复
```

## 4. 持仓管理模块（4个接口）

### 获取组合持仓列表
```
GET /api/portfolios/{portfolio_code}/positions
Query: date?（默认最新日期）
Response: [ {
  id, product_code, market,
  shares, cost_price, unit_price,
  market_value, profit, profit_pct,
  snapshot_date
} ]
规则：
- 不传date → 查询 MAX(snapshot_date)
- 传入date → 查询指定日期历史持仓
```

### 持仓收益归因分析
```
GET /api/portfolios/{portfolio_code}/positions/attribution
Response: [ { product_code, contribution: {...}, contribution_pct } ]
```

### 获取可用现金
```
GET /api/portfolios/{portfolio_code}/available-cash
Response: { 
  snapshot_cash,           // 快照现金
  pending_in,              // pending申购
  pending_out,             // pending赎回
  pending_buy,             // pending买入
  confirmed_in,            // confirmed申购（快照未生成）
  confirmed_out,           // confirmed赎回（快照未生成）
  confirmed_buy,           // confirmed买入（快照未生成）
  confirmed_sell,          // confirmed卖出（快照未生成）
  available_cash           // 可用现金（实时计算结果）
}
```

**实时计算逻辑**：
```
available_cash = snapshot_cash 
               + confirmed_in      // 已确认申购（快照未生成）
               - confirmed_out     // 已确认赎回（快照未生成）
               - pending_buy       // pending买入
               - confirmed_buy     // 已确认买入（快照未生成）
               + confirmed_sell    // 已确认卖出（快照未生成）
```

> ⚠️ **重要**：前端展示可用现金时必须使用 `available_cash` 字段，不能仅使用 `snapshot_cash`。

### 批量更新非净值型资产金额
```
PATCH /api/portfolios/{portfolio_code}/positions/non-nav-assets
Body: { 
  updates: [ 
    { product_code, amount, effective_date? }, 
    ... 
  ] 
}
Response: { updated_count, positions: [...] }

规则：
- 仅允许更新非净值型资产（product_code 为 CASH）
- 支持批量更新
- 仅处理有变化的记录
- effective_date 可选，默认当天（格式 YYYY-MM-DD）
- effective_date 必须是交易日（非交易日拒绝操作）

后端实现逻辑：
1. 记录现金变动事件到 cash_change 表（若存在）或直接标记为待更新
2. 变动立即生效，等待每日快照汇总更新
3. 若需立即查询，实时计算：快照金额 + 当日现金进出变动
4. market 默认为 NULL（现金类资产无市场）

> ⚠️ **说明**：现金进出是一种即时生效的操作，不像申购/赎回需要T+1确认。但为保持快照管理的一致性，仍应等待每日快照汇总更新。查询可用现金时需实时计算。
```

## 5. 申购赎回管理模块（7个接口）

**业务规则**：
- 申购：资金进入组合，份额增加
- 赎回：资金退出组合，份额减少

**交易日校验**：
- 所有交易操作（申购、赎回、调仓、现金进出）仅允许在交易日进行
- 非交易日提交交易时返回错误：`{ error: "NON_TRADING_DAY", message: "非交易日，请等待交易日再提交" }`

**输入单位说明**：
- 申购：输入**金额**（元），系统计算份额 = 金额 / T日净值
- 赎回：输入**份额**（份），系统计算金额 = 份额 × T日净值
- 前端应显示预估金额/份额供用户参考

### 提交申购
```
POST /api/portfolios/{portfolio_code}/subscriptions
Body: { 
  investor_code, 
  sub_type: "subscribe", 
  amount,        // 申购金额（元），如 10000
  apply_date, 
  notes? 
}
Response: { 
  id, 
  investor_code, 
  sub_type: "subscribe", 
  amount,          // 申购金额
  unit_price,      // T日净值（确认时填入）
  shares,          // 确认份额 = amount / unit_price
  status: "pending" 
}
说明：
- amount: 用户输入的申购金额（元）
- shares: 确认后计算得出 = amount / T日净值
```

### 提交赎回
```
POST /api/portfolios/{portfolio_code}/redeems
Body: { 
  investor_code, 
  shares,        // 赎回份额（份），如 5000
  apply_date, 
  notes? 
}
Response: { 
  id, 
  investor_code, 
  sub_type: "redeem", 
  shares,           // 赎回份额
  estimated_amount, // 预估金额（基于最近净值）
  estimated_nav,    // 预估净值
  available_shares, // 可用份额
  status: "pending" 
}
说明：
- shares: 用户输入的赎回份额（份），必须 <= 可用份额
- estimated_amount: 预估金额仅供参考，实际金额以T日净值计算
- amount: 确认后计算得出 = shares × T日净值
- 前端应显示预估金额，并提示"实际金额以T日净值计算为准"
```

### 获取申购记录列表
```
GET /api/portfolios/{portfolio_code}/subscriptions
Query: status?, investor_code?, start_date?, end_date?, page?, page_size?
Response: { items: [...], total, page, page_size }
规则：默认返回申购记录（sub_type='subscribe'）
```

### 获取赎回记录列表
```
GET /api/portfolios/{portfolio_code}/redeems
Query: status?, investor_code?, start_date?, end_date?, page?, page_size?
Response: { items: [...], total, page, page_size }
说明：专用路径，无需 sub_type 参数
```

### 获取申购详情
```
GET /api/subscriptions/{id}
Response: { id, investor_code, sub_type, amount, shares, unit_price, apply_date, confirm_date, status, notes }
```

### 获取赎回详情
```
GET /api/subscriptions/{id}
规则：通过 sub_type='redeem' 筛选赎回记录
Response: { id, investor_code, sub_type, amount, shares, unit_price, apply_date, confirm_date, status, notes }
```

### 确认申购/赎回
```
POST /api/subscriptions/{id}/confirm
Body: { confirm_date?, unit_price? }
Response: { id, status: "confirmed", shares, confirm_date }
规则：场外T+1确认，默认下一个交易日
```

## 6. 调仓交易管理模块（7个接口）

**业务规则**：
- 买入：现金减少，份额增加
- 卖出：现金增加，份额减少
- 调仓不改变组合总份额
- 场外买入提交时冻结现金
- **现金中转约束**：调仓必须通过现金中转，不能直接基金对基金转换
  - 卖出基金：所得资金进入组合现金池（需等待确认）
  - 买入基金：从组合现金池支出（只能使用已有可用现金）
  - 卖出pending不自动增加可用现金

### 创建买入交易
```
POST /api/portfolios/{portfolio_code}/trades/buy
Body: {
  product_code,
  market,                          -- CN_EXCHANGE/CN_OTC（LOF必填）
  actual_amount,                   -- 实际支付金额
  fee,                             -- 手续费
  price?,                          -- 成交价格（默认从price_record获取）
  trade_date,
  platform_code?,
  notes?
}
Response: { id, product_code, shares, amount, price, fee, actual_amount, status }
计算：amount = actual_amount - fee，shares = amount / price
```

### 创建卖出交易
```
POST /api/portfolios/{portfolio_code}/trades/sell
Body: {
  product_code,
  market,
  actual_amount,                   -- 实际到账金额
  fee,
  price?,
  trade_date,
  platform_code?,
  notes?
}
Response: { id, product_code, shares, amount, price, fee, actual_amount, status }
计算：amount = actual_amount + fee，shares = amount / price
```

### 获取交易记录列表
```
GET /api/portfolios/{portfolio_code}/trades
Query: status?, trade_type?, product_code?, market?, start_date?, end_date?, page?, page_size?
Response: { items: [...], total, page, page_size }
```

### 获取交易详情
```
GET /api/trades/{id}
Response: { id, portfolio_code, product_code, market, trade_type, shares, amount, price, fee, actual_amount, trade_date, confirm_date, frozen_amount, status, notes }
```

### 确认交易
```
POST /api/trades/{id}/confirm
Body: { confirm_date?, price?, fee? }
Response: { id, status: "confirmed", shares, fee, actual_amount, confirm_date }
规则：
- 场内：当天确认（使用收盘价）
- 场外：T+1确认（使用T日净值）
- QDII：T+2确认
```

### 取消交易
```
POST /api/trades/{id}/cancel
Body: { reason? }
Response: { id, status: "cancelled" }
规则：仅场外待确认状态可取消，释放冻结现金
```

### 批量调仓
```
POST /api/portfolios/{portfolio_code}/trades/batch
Headers: {
  "X-Idempotency-Key": "uuid"  // 客户端生成的唯一标识，用于幂等性控制
}
Body: { 
  trade_date, 
  items: [
    {
      product_code,
      market,
      trade_type,    // 'buy' 或 'sell'
      shares?,       // 卖出时必填，买入时忽略
      amount?        // 买入时必填，卖出时忽略
    }
  ] 
}
Response: { 
  idempotency_key,  // 返回幂等性Key
  trades: [...], 
  total_buy_amount, 
  total_sell_amount, 
  cash_change 
}

规则：
- 客户端必须生成唯一的 Idempotency-Key（UUID）
- 服务端检查该Key是否已处理：
  - 已处理：直接返回缓存的结果
  - 未处理：正常执行并缓存结果（24小时有效期）
- 一次性提交多笔调仓，原子性处理
- 幂等性保证：相同Key的请求多次调用，只执行一次

现金中转约束：
- 卖出和买入是独立交易，独立确认
- 买入金额不能超过组合已有可用现金（不含本次卖出的pending金额）
- 若现金不足，需分两步操作：
  1. 先提交卖出交易，等待确认
  2. 确认后可用现金增加，再提交买入交易
- 示例：
  - 组合现金：1000元
  - 卖出基金A：5000元（pending）
  - 买入基金B：6000元（pending）
  - 结果：拒绝买入，因为可用现金=1000元（不含卖出pending的5000元）
```

## 7. 份额变动事件管理模块（8个接口）

### 创建份额变动事件
```
POST /api/share-change-events
Body: { 
  portfolio_code, 
  product_code, 
  market, 
  event_type, 
  event_date, 
  entitlement_date,  -- 必须是交易日
  div_cash?, 
  ratio?, 
  cash_product_code?, 
  ... 
}
Response: { id, status: "pending" }
event_type: cash_dividend | reinvest_dividend | share_split | share_merge | bonus_share | forced_adjustment

校验规则：
- 权益登记日必须是交易日（查询 trading_calendar 表 is_open = true）
- 非交易日返回错误：{ error: "INVALID_ENTITLEMENT_DATE", message: "权益登记日必须是交易日" }
- 创建时不校验持仓快照是否存在
- status 默认为 "pending"
```

### 获取份额变动事件详情
```
GET /api/share-change-events/{id}
Response: { 
  id, portfolio_code, product_code, market,
  event_type, event_date, entitlement_date,
  shares_before, shares_change, shares_after,
  cash_change, status, notes, created_at
}
```

### 查询份额变动事件列表
```
GET /api/share-change-events
Query: 
  portfolio_code?,    -- 组合编码
  status?,            -- pending/confirmed/cancelled
  start_date?,        -- 事件日期范围（开始）
  end_date?,          -- 事件日期范围（结束）
  page?, page_size?
Response: { 
  items: [...], 
  total, page, page_size 
}
```

### 删除份额变动事件
```
DELETE /api/share-change-events/{id}
Response: { message: "删除成功" }
规则：仅待处理(pending)状态可删除
```

### 取消份额变动事件
```
POST /api/share-change-events/{id}/cancel
Response: { id, status: "cancelled" }
规则：仅待处理(pending)状态可取消
```

### 同步分红数据
```
POST /api/share-change-events/sync-dividends
Body: { start_date?, end_date? }
Response: { synced_count, new_events: [...] }
```

### 确认份额变动事件
```
POST /api/share-change-events/{id}/confirm
Response: { 
  id, 
  status: "confirmed",
  entitlement_shares,
  shares_change,
  cash_change 
}

校验规则：
- 必须校验权益登记日对应的持仓快照是否存在
- 查询 portfolio_position 表 WHERE snapshot_date = entitlement_date
- 若快照不存在，返回错误：{ error: "MISSING_POSITION_SNAPSHOT", message: "权益登记日持仓快照不存在，请先生成快照" }
- 获取权益登记日持仓份额，计算份额变化和现金变化
- 更新 share_change_event 记录并标记为 confirmed
```

### 批量确认事件
```
POST /api/share-change-events/batch-confirm
Body: { events: [ { id, shares_after?, amount_received? } ] }
Response: { success_count, failed_count, details: [...] }

校验规则：
- 每个事件独立校验持仓快照是否存在
- 校验失败的事件计入 failed_count，不影响其他事件
- details 中包含每个事件的校验结果和错误信息
```

## 8. 市场数据模块（3个接口）

**市场-接口映射**：

**Tushare API 限流规则**：

| 限制项 | 限制值 | 说明 |
|--------|--------|------|
| 调用频次 | 200次/分钟 | 需在代码中实现限流 |
| 单次返回量 | 5000条 | 超出需分页获取 |

**限流实现**：
```python
# 全局限流器
tushare_limiter = RateLimiter(calls_per_minute=200)

def call_tushare_api(api_func, *args, **kwargs):
    tushare_limiter.wait()  # 调用前等待
    return api_func(*args, **kwargs)
```

## 15. 枚举值定义

### 角色（investor.role）
- `admin`：创建组合、添加投资人、编辑交易记录、管理产品
- `viewer`：查看组合详情、持仓明细、收益曲线

### 市场类型（product.market）
- `CN_EXCHANGE`：A股场内（ETF/LOF场内）
- `CN_OTC`：内地场外（OEF/LOF场外）
- `HK_MUTUAL`：香港互认基金
- `NULL`：现金类产品

### 产品类型（product.product_type）
- `ETF`：场内交易基金
- `OEF`：开放式基金
- `LOF`：上市开放式基金
- `CASH`：现金类资产（含货币基金）

### 交易类型（trade.trade_type）
- `buy`：买入
- `sell`：卖出

### 交易状态（trade/subscription.status）
- `pending`：待确认
- `confirmed`：已确认
- `cancelled`：已取消

### 事件类型（share_change_event.event_type）
- `cash_dividend`：现金分红（份额不变，现金增加）
- `reinvest_dividend`：分红再投资（份额增加）
- `share_split`：份额拆分
- `share_merge`：份额合并
- `bonus_share`：送股
- `forced_adjustment`：强制调整

### 现金账户（share_change_event.cash_product_code）
- `CASH`：现金类资产

### 数据源状态（product.data_source_status）
- `pending`：待校验
- `success`：成功
- `failed`：失败
