## 1. 概述

### 1.1 设计目标

日志系统用于记录系统运行过程中的关键事件，支持：
- 安全审计：追踪用户操作行为
- 问题排查：定位系统异常原因
- 运行监控：了解系统运行状态
- 合规要求：满足金融系统审计需求

### 1.2 日志类型

| 类型 | 说明 | 优先级 |
|------|------|--------|
| 登录日志 | 记录用户登录/登出行为 | 必须 |
| 操作审计日志 | 记录关键业务操作 | 必须 |
| 任务执行日志 | 记录定时任务执行情况 | 必须 |
| 净值同步明细 | 记录每只基金同步结果 | 必须 |
| 系统错误日志 | 记录系统异常 | 必须 |
| API访问日志 | 记录接口调用情况 | 可选 |
| 通知日志 | 记录通知发送情况 | 可选 |

## 2. 数据库设计

### 2.1 登录日志表（login_log）

```sql
CREATE TABLE login_log (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    investor_code TEXT NOT NULL,           -- 登录用户
    action TEXT NOT NULL,                  -- login/logout/login_failed
    status TEXT NOT NULL,                  -- success/failed
    ip_address TEXT,                       -- 登录IP
    user_agent TEXT,                       -- 浏览器信息
    failure_reason TEXT,                   -- 失败原因
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_login_log_investor ON login_log(investor_code, created_at DESC);
CREATE INDEX idx_login_log_status ON login_log(status, created_at DESC);
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| action | TEXT | login=登录, logout=登出, login_failed=登录失败 |
| status | TEXT | success=成功, failed=失败 |
| failure_reason | TEXT | 密码错误/账户锁定/账户不存在等 |

### 2.4 任务执行日志表（task_execution_log）

```sql
CREATE TABLE task_execution_log (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    task_code TEXT NOT NULL,               -- 任务代码

CREATE INDEX idx_task_log_task ON task_execution_log(task_code, started_at DESC);
CREATE INDEX idx_task_log_status ON task_execution_log(status, started_at DESC);
```

**状态定义**：

| status | 说明 |
|--------|------|
| running | 执行中 |
| success | 成功 |
| failed | 失败 |

GET /api/system/logs/error

## 5. 定时任务调度器实现

### 5.1 技术选型

使用 **APScheduler** 作为定时任务调度器：

```python
from apscheduler.schedulers.background import BackgroundScheduler
from apscheduler.executors.pool import ThreadPoolExecutor

# 单线程执行器，确保任务串行执行（避免 SQLite 并发写入冲突）
executors = {
    'default': ThreadPoolExecutor(max_workers=1)
}

scheduler = BackgroundScheduler(executors=executors)
scheduler.start()
```

### 5.2 任务配置

| 任务编码 | 任务名称 | Cron 表达式 | 说明 |
|----------|----------|-------------|------|
| nav_sync | 净值同步 | 0 7 * * 1-5 | 每个交易日07:00，增量同步 |
| trading_calendar_sync | 交易日历同步 | 0 2 1 1 * | 每年1月1日02:00 |
| log_cleanup | 日志清理 | 0 4 * * 0 | 每周日04:00 |

### 5.3 并发控制策略

由于 SQLite 不支持高并发写入，采用以下策略：

1. **单线程执行器**：所有定时任务串行执行
2. **WAL 模式**：读写可并发（见 02-数据库设计.md）
3. **错峰调度**：不同任务安排在不同时间点执行
4. **手动触发排队**：admin 手动触发任务时，检查是否有任务正在执行

```python
# 任务执行状态检查
def is_task_running():
    return scheduler.get_jobs() and any(
        job.next_run_time is None for job in scheduler.get_jobs()
    )
```

### 5.4 任务执行流程

```
定时任务触发
┌─────────────────────────────────────────────────────────────┐
│  1. 检查是否有其他任务正在执行                                │
│     - 若有：等待或跳过（可配置）                              │
│     - 若无：继续执行                                         │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  2. 创建任务执行日志                                         │
│     - INSERT INTO task_execution_log (task_code, status='running')    │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  3. 执行任务逻辑                                             │
│     - 记录开始时间、结束时间                                  │
│     - 记录执行结果（成功/失败/部分成功）                      │
│     - 记录详细日志（如净值同步明细）                          │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  4. 更新任务执行日志                                         │
│     - UPDATE task_execution_log SET status='completed', ...           │
└─────────────────────────────────────────────────────────────┘
```
