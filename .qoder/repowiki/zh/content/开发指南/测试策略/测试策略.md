## 引言
本测试策略文档面向 InvestRing 项目，旨在为后端 API、数据库、异步任务提供系统化的测试实施计划。文档覆盖单元测试、集成测试、端到端测试和性能测试，明确测试框架（pytest）、Mock 使用、测试数据准备、测试环境配置、覆盖率要求、CI 流程与自动化脚本，并补充性能与安全测试指导。

**更新** 新增了全面的负现金场景测试、交易现金验证逻辑测试和CLI错误处理测试，显著增强了系统的健壮性和错误处理能力。这些新增的测试套件确保了投资组合在极端情况下的数据一致性，交易操作的现金余额准确性，以及命令行工具的友好错误提示。同时，多数据库支持的增强确保了测试套件在多种数据库后端（SQLite、MySQL、PostgreSQL）上的一致性和稳定性。

## 项目结构
项目采用前后端分离架构：
- 后端基于 FastAPI，提供 REST API，使用 SQLAlchemy 进行数据库访问，支持异步任务与定时任务。
- 前端基于 Next.js + React，使用 TanStack React Query 管理数据请求，Zustand 管理轻量状态，Axios 封装 API 调用与统一错误处理。
- CLI 工具提供命令行界面，与 REST API 保持一致的业务逻辑，新增Schema功能测试确保数据格式一致性。
- 测试框架包括 Python 的 pytest 与 Playwright 端到端测试，分别覆盖后端 API、CLI 工具与前端交互。

### 基于 Monkeypatching 的服务提交验证测试
- 核心测试类与方法
  - `TestServiceNoCommit`：专门验证服务层不应产生未经授权的数据库提交操作
  - `test_no_commit_on_read_operations`：验证只读操作不会产生数据库提交
  - `test_no_commit_on_validation_only`：验证纯验证操作不会触发数据库提交
  - `test_monkeypatch_session_commit`：使用 monkeypatching 技术拦截并验证 commit 调用

- 关键测试场景
  - **只读操作保护**：所有查询操作应严格避免数据库提交
  - **验证操作隔离**：数据验证逻辑不应产生副作用
  - **Monkeypatching 技术**：通过替换 session.commit 方法验证提交行为
  - **事务边界控制**：确保服务层正确的事务边界管理
