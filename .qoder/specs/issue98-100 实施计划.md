## 3. 关键算法 / 口径

### 3.1 total_profit（组合概要派生字段）
```
net_invested = Σ sub.amount (status='confirmed' AND sub_type='subscribe')
             − Σ sub.amount (status='confirmed' AND sub_type='redeem')
total_profit = latest_snapshot.total_value − net_invested   # 无快照 → None
```

### 3.2 持仓行收益（读侧派生，路线 C：分红加回基金 + 事件计入现金基数）

**口径推演（用户评审确认）**：基金分红 100 元 → 除权日基金市值 −100、现金 +100、组合总资产不变。
- 路线 A（仅现金侧事件入基数）：基金 +100、现金 0，合计 +100 ≠ total_profit +200 ✗
- 路线 B（仅现金侧事件入收益）：基金 +100（除权记损）、现金 +100（白捡），合计 +200 ✓ 但单资产失真 ✗
- **路线 C（采用）**：基金侧加回分红（复权口径）+ 现金侧事件入基数 → 基金 +200、现金 0，合计 +200 ✓ 且不失真

```
profit_loss（累计，读侧派生）：
  非现金行 = market_value − shares×cost_price + Σ share_change_event.cash_change(该产品/平台)
             # 现金分红加回 = 复权口径；拆分/合并事件 cash_change=0 天然无影响
  现金行   = 见 3.3

daily_profit：
  对每个持仓行 r（portfolio P, 产品 prod, 平台 plat, 当前快照日 d）：
    if P 的首个快照日 == d:  → None                    # 无前日基准
    if prod in (IN_TRANSIT_BUY, IN_TRANSIT_SELL): → None
    prev_d = max(snapshot_date) where snapshot_date < d  (P 维度，快照断层取最近可得)
    mv_prev = position(P, prod, plat, prev_d).market_value or 0
    非现金行：daily_profit = r.market_value − mv_prev
              − Σ trade(prod, plat, d)(买入−卖出)      # 当日交易净流入
              + Σ event(prod, plat, ex_date=d).cash_change   # 当日分红加回，对冲除权（分红日 daily=0）
    现金行：  daily_profit = cash_d − cash_prev_d − 当日净流入（见 3.3，含事件）
```
分红日效果：基金 daily = −100 + 100 = 0，现金 daily = +100 − 100 = 0，合计 0 = 总资产真实变化 ✓，且「累计 = Σ 每日 daily」恒成立。
前一快照日查询先例：`snapshot_service.py` L807-809 / L1120-1122。事件聚合按 (product_code, platform_code) 维度批量查询（实施时 Read share_change_event 模型核对平台列名）。

### 3.3 现金累计收益 / 现金净资金流入（按平台聚合，路线 C）
```
transfer_group 分类：'sub_' 前缀=申赎外部流；'rebal_' 前缀=调仓内部流；其余(裸uuid)=跨平台转移
对平台 plat 的 CASH 行：
  累计净存入 = Σ sub_ 流入(plat) − Σ sub_ 流出(plat)
  累计买入   = Σ rebal_ 现金腿流出(plat)（买产品花现金）
  累计卖出   = Σ rebal_ 现金腿流入(plat)
  转移净额   = Σ 转移双腿中流入(plat) − 流出(plat)
  事件净额   = Σ share_change_event.cash_change(plat)
  现金累计收益(=CASH 行 profit_loss) = 当前现金(plat) − (累计净存入 − 累计买入 + 累计卖出 + 转移净额 + 事件净额)
  当日现金净资金流入(plat, d) = 上述五项（sub_/rebal_/转移/事件）按日 d 过滤之和
```

**口径要点（与 §3.2 路线 C 配套，已与用户推演确认）**：
- 事件净额计入存入基数 → 现金累计收益 ≈ 0，仅吸收 manual_market_value 手动调平 / 利息等未记账差额（与评审「恒 ≈ 0」预期一致）；分红对现金而言是「从基金形态转入的已实现收益」，不是现金自身创造的收益，故不计入现金收益。
- 自洽性由基金侧「分红加回」（§3.2）保证：基金 profit_loss/daily_profit 加回归属该产品的现金分红，除权损失被对冲，两侧卡片合计 = 总资产 − 净投入（无清仓场景）= total_profit ✓。
- 跨平台转移双腿同组同日分别计入各自平台（不可净额抵消），否则单平台卡片出现虚假 ±N 盈亏。
- **已知边界**：已清仓产品的已实现盈亏不体现在持仓卡片（持仓分区只含当前持仓），此时卡片合计与 total_profit 的差值 = 已清仓产品已实现盈亏，属持仓分析视图的固有边界，PR 描述注明。

实现注意：trade 表汇总一次 SQL（GROUP BY platform + 前缀分类用 CASE WHEN，双方言兼容），不要逐行 Python 循环；share_change_event 聚合同样一次批量查询按 (product_code, platform_code) 建映射。实现前 Read `backend/app/models/trade.py` 与 `share_change_event` 模型核对列名（本次未逐行读全）。

### 3.4 最大余数法占比（饼图/分区通用）
```
输入 weights w_i（Σw=1），精度 1 位小数（千分位整数）：
  raw_i = w_i * 1000
  floor_i = floor(raw_i)
  remainder = 1000 − Σfloor_i
  按 (raw_i − floor_i) 降序，前 remainder 项 +1
  输出 floor_i / 10（%）
```
放在 `frontend/src/lib/utils.ts` 新函数 `largestRemainderPercents(weights: number[]): number[]`，饼图与分区头共用，杜绝 ±0.1%×n 漂移。

## 5. 风险点与缓解

1. **_period_return 口径统一 = 存量行为变更**：成立不足 1m/3m 的组合收益率由「成立以来」变 None，既有测试断言与可能的用户预期受影响。缓解：先跑全量 pytest 定位受影响断言逐条改；PR 描述显式声明行为变更；docstring 同步修正消除文档/代码漂移。**另需验证 commit 3 落地后、commit 4 前的中间态**：旧前端 PerformanceMetrics 仍在展示 return_1m/3m/ytd，这些字段值可能由数值变 None——commit 3 完成时快速检查 PerformanceMetrics 对 null 的渲染兜底（如显示 NaN/崩溃则在 commit 3 顺手补 null 兜底，不等 commit 4）。
2. **迁移执行顺序**：生产/CI 先 `create_all` 后 `alembic upgrade head`（0005 注释）→ 新库列已存在，0007 靠 inspector 守卫 no-op；老库（仅 alembic 管理）正常 add_column+回填。两路径都要测；回填 `WHERE asset_name IS NULL` 保证重跑幂等。
3. **Next 15 searchParams**：两详情页均为 `"use client"`，`useSearchParams` 必须包 `<Suspense>` 否则 `next build` 预渲染报错；useParams 不受影响。若页面未来改服务端组件，searchParams 是 Promise 需 await——本次保持客户端组件不迁移。
4. **positions enrichment N+1**：所有派生（product 名/asset_class_code/asset_name/前日市值/当日流水）必须批量查询+内存映射，沿用 L56-72 现有模式；测试用例覆盖多产品场景防回归。
5. **现金/基金收益口径错算（路线 C 双侧配套）**：transfer_group 前缀分类 CASE WHEN 须覆盖 'sub_%'/'rebal_%'/其余三类；跨平台转移双腿同组同日分别计入各自平台；事件 cash_change 一侧入现金基数、另一侧加回基金行 profit_loss/daily_profit——**两侧必须同时实现，只做一侧必然失真或破坏合计自洽**（已通过与用户的三路线推演确认）。缓解：§3.2/§3.3 公式评审后再写 SQL，测试构造四类流水 + 分红日复权混合用例；事件与持仓行的 (product, platform) 维度匹配需实施时核对 share_change_event 模型平台列。
6. **饼图/分区占比漂移**：统一走 largestRemainderPercents，禁止各处自行 toFixed(1)。
7. **NavCurveSimple 删除**：已确认仅 m/portfolio 详情引用，commit 5 内同 PR 删除，无孤儿引用风险。
